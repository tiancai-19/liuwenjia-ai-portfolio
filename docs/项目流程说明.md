# 项目流程说明（面试讲清楚"你怎么做的"）

> 每个项目都用 **PARL** 结构讲：Problem（问题）→ Action（行动）→ Result（结果）→ Lesson（踩坑）。
> 下面把三个项目的流程拆成可复述的步骤，面试时照这个讲。

## 通用交付流程（全项目通用）
1. **需求调研**：用 JTBD + Mom Test 收敛业务痛点（别说"用户要个系统"，说"用户每周花 X 小时做 Y"）
2. **方案设计**：画数据流图，定技术选型（低代码 vs 写代码，要说清为什么）
3. **原型验证**：先用最简版本跑通主路径，给业务方看偏差
4. **开发联调**：前端 + 后端/AI + 数据库，每完成一个功能就本地验证
5. **测试上线**：接口测试 + 边界用例（缺参数、格式错、超时）
6. **效果跟踪**：量化节省时间 / 准确率 / 覆盖率，持续迭代
7. **资产沉淀**：把 Prompt、工作流模板、文档归拢，下次复用

## 项目 1 · AI 简历优化 + 模拟面试
- 痛点：不会写简历 + 面试没练
- 我的动作：设计"优化 + 模拟面试"双功能；前端收集简历文本 + 岗位；调大模型 API 流式输出
- 关键决策：只优化不代写（真实性卖点，也避伦理风险）
- 结果：可在线演示

## 项目 2 · 企业知识库问答（RAG）
- 痛点：文档散、查得慢、大模型幻觉
- 我的动作：解析→语义分块→Embedding→Chroma→检索→拼接→生成→引用
- 关键决策：语义分块 + 重叠区（解决跨段问题）；答案强制附原文引用
- 结果：能答业务问题且可溯源

## 项目 3 · 电商运营自动化
- 痛点：图文/对账/客服三类重复劳动
- 我的动作：AIGC 工作台（接真实 API + 落库）、pandas 对账升级、Coze 客服 bot
- 关键决策：原型案例必须接真实 API 才有价值，不能停留在假数据
- 结果：三类流程自动化，量化节省工时
